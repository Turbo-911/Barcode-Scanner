================================================================================
                    QA BARCODE TEST IMAGES SUITE
================================================================================

All test BMP files in this directory are valid Interleaved 2 of 5 (ITF) barcodes
matching the team's ITF encoding specification (src/barcode/encoder.cpp and
README.md). They are 8-bit grayscale BMPs directly readable by loadBMP
(src/common/BMP.cpp).

Run them - they are no longer just files on disk (D-13):
  barcode_studio_gui.exe --selftest
decodes every stress file below, plus the in-memory round trip and a
decode-back check of every barcode in barcodes/. The console menu
(--console, option 4) runs the same in-memory + stress-file checks.
The POS service checks live in tests/pos_selftest.cpp; build and run
them in a fresh temp folder with:
  mingw32-make -f Makefile.gui test
Never run pos_selftest from the repo root - it seeds (truncates)
Data/*.txt in its working directory, and it refuses to run against a
non-empty catalogue.

There is no setup_qa.bat. To regenerate a barcode image, use the GUI
Generator screen or the console menu (--console, option 1); the
encoder is src/barcode/encoder.cpp, the decoder src/barcode/Decoder.cpp.

--------------------------------------------------------------------------------
2. QA Stress Test & Edge Case Barcodes:
--------------------------------------------------------------------------------
- test_normal.bmp     ->  Expected Decoded Digits: 123456 (Baseline crisp capture)
- test_rotated.bmp    ->  Expected Decoded Digits: 987654 (180-deg inverted / upside-down)
- test_blurry.bmp     ->  Expected Decoded Digits: 555555 (Blurred edges / low contrast)
- test_noisy.bmp      ->  Expected Decoded Digits: 888888 (Salt & pepper noise)
- test_small.bmp      ->  Expected Decoded Digits: 314159 (Small module size: 2px)
- test_large.bmp      ->  Expected Decoded Digits: 654321 (Large module size: 4px)
- test_inverted.bmp   ->  Expected Decoded Digits: 123456 (Genuinely inverted polarity:
                          every pixel of test_normal.bmp flipped, white-on-black.
                          The old file was only a 180-degree rotation, the same
                          case test_rotated.bmp already covered, so it tested
                          nothing about inversion. The decoder tries the
                          inverted scanline (255 - v) as a fallback.)

NOTE on 555555: it is only the code inside test_blurry.bmp, a decode
test with no product behind it. It is NOT White Sugar - White Sugar is
145555 (Data/product.txt) - and it is no longer used as a demo barcode
anywhere (D-10). The canonical demo barcodes are 145555 and 111001.
